# P2 채널별 CSV 정규화·구글시트 반영 설계 검토

## 결론

확정 방향은 타당함. 핵심은 채널별 해석 규칙을 로컬 코드와 버전 관리 가능한 설정으로 고정하고, 정규화 결과 검증이 끝난 뒤에만 구글시트 출력 어댑터를 호출하는 구조. 파일명이나 시트 수식에 의미 해석을 맡기지 않고, 모호한 입력은 추정 대신 실패 처리하는 방식 권장.

다만 `날짜·채널·캠페인`을 유일 키로 간주할 때 원본의 추가 차원을 제거하면서 중복 키가 생길 수 있음. MVP에서는 원본 행 단위 변환을 기본으로 하고, 동일 키 중복 발견 시 자동 합산 대신 검증 실패 처리. 추후 지표별 가산 가능성과 추가 차원 정의가 확정된 뒤 집계 단계 도입.

## 목표 흐름

`입력 폴더 탐색 → CSV 구조 해석 → 헤더 지문 기반 채널 판별 → 채널별 매핑 → 공통 형식 변환 → 의미·품질 검증 → 로컬 산출물 확정 → 구글시트 업로드 → 업로드 검증`

목표 설계에서 정규화 엔진의 반환값은 데이터 행, 실행 메타데이터, 검증 결과의 세 묶음. 현재 MVP는 데이터 행과 행 단위 메타데이터를 채널별 CSV로 반환하며 별도 실행·검증 보고서는 미구현. 구글시트 어댑터는 정규화 CSV만 입력으로 받고 원본 CSV 해석이나 지표 계산은 담당하지 않는 구조.

| 출력 통합 테스트 | `tests/integration/test_google_sheets_output.py` |
| 정규화 산출물 | `output/normalized/`의 채널별 CSV 5개 |

정규화 결과는 GA4 42행, Meta 42행, 네이버 검색광고 28행, 네이버 GFA 28행, 카카오 모먼트 14행의 총 154행. 단일 통합 CSV 대신 채널별 CSV와 구글시트 탭의 일대일 대응.

구글시트 출력은 5개 채널 탭과 선택적 `전주비교` 탭을 대상으로 탭 생성, 대상 범위 초기화, 한글 표시값의 `RAW` 일괄 쓰기, 전체 범위 재조회 대조, 서식 반영의 순서. 채널 탭 154행과 전주 비교 88행을 합한 242개 데이터 행 및 헤더 포함 4,127개 셀 반영 검증.

임시 탭 교체, 실행 기록 탭, 검증 이슈 탭, 실행 해시 기반 멱등성은 운영 확장안으로 유지. 현재 MVP의 재실행 중복 방지는 대상 탭 전체 초기화 후 재작성 방식.

정규화 전용 자동화 테스트는 현재 부재. 출력 어댑터 통합 테스트 8건은 통과 상태이나, 정규화기의 헤더 판별·날짜 변환·실패 조건에 대한 회귀 테스트 추가 필요.

## 권장 구성

| 구성 요소 | 책임 | 주요 산출물 |
|---|---|---|
| 입력 탐색기 | 입력 폴더의 CSV 목록 확정, 파일 해시 계산 | 입력 파일 목록 |
| CSV 판독기 | UTF-8 BOM, 인용부호, GA4 주석행 처리 | 헤더와 원본 행 |
| 채널 판별기 | 헤더 지문과 필수 컬럼 조합 비교 | 채널 코드와 판별 근거 |
| 채널 어댑터 | 컬럼명·날짜·숫자 형식 변환, 메타데이터 부여 | 공통 스키마 행 |
| 검증기 | 스키마, 값, 행 수, 합계, 중복 키, 의미 충돌 검사 | 오류·경고 목록 |
| 로컬 출력기 | 검증된 데이터와 실행 기록 저장 | 정규화 CSV, 실행·검증 JSON |
| 구글시트 어댑터 | 인증, 일괄 쓰기, 재실행 중복 방지, 결과 대조 | 시트 반영 결과 |

채널 규칙은 코드에 흩어진 조건문보다 `channel_registry` 형태의 명시적 매핑으로 관리. 규칙 버전, 필수 헤더, 선택 헤더, 원본→공통 컬럼 매핑, 날짜 파서, VAT 기준, 전환 정의를 한곳에 보존.

## 공통 스키마

### 데이터 필드

| 필드 | 형식 | 규칙 |
|---|---|---|
| `date` | `YYYY-MM-DD` | 원본 날짜의 표준화 |
| `channel` | 고정 코드 | `ga4`, `meta`, `naver_search`, `naver_gfa`, `kakao_moment` |
| `campaign` | 문자열 | 원본 캠페인명 유지. 접두사 제거와 채널 간 이름 통합 제외 |
| `cost` | nullable 정수 | 원 단위. 원본 부재 시 결측 |
| `impressions` | nullable 정수 | 원본 부재 시 결측 |
| `clicks` | nullable 정수 | 원본 부재 시 결측 |
| `conversions` | nullable 정수 | 원본 정의 유지. 서로 다른 정의 간 합산 금지 |
| `revenue` | nullable 정수 | 원 단위. 원본 부재 시 결측 |

빈 문자열, 미제공, 파싱 실패를 모두 0으로 바꾸지 않는 구분 필요. 미제공과 빈 값은 결측, 파싱 실패는 오류. 비용·매출은 부동소수점보다 원 단위 정수 사용 권장.

### 메타데이터 설계와 구현

- `source_file`, `source_row_number`, `source_file_hash`: 원본 추적 정보
- `adapter_version`, `schema_version`: 구현된 규칙 재현 정보
- `vat_basis`: `included`, `excluded`, `unknown`, `not_applicable` 중 하나
- `conversion_definition`: `주요 이벤트`, `구매`, `구매완료` 등 원본 정의
- `revenue_definition`: `총 수익`, `전환매출액`, `전환값` 등 원본 정의
- `source_dimensions`: GA4의 `세션 기본 채널 그룹`처럼 공통 스키마에서 제외된 원본 차원

위 필드는 현재 채널별 CSV와 시트 탭에 포함. `run_id`, `normalized_at`, 별도 실행 기록은 운영 확장 범위. 시트 사용 편의를 위해 주요 의미 필드인 `vat_basis`, `conversion_definition`, `revenue_definition`도 데이터 탭에 포함.

## 실제 5종 판별·매핑

| 채널 | 헤더 지문 | 날짜 | 비용 | 노출·클릭 | 전환 | 매출 | 의미 메타데이터 |
|---|---|---|---|---|---|---|---|
| GA4 | `날짜`, `세션 기본 채널 그룹`, `세션 캠페인`, `주요 이벤트 수`, `총 수익` | `날짜` | 결측 | 결측 | `주요 이벤트 수` | `총 수익` | VAT `not_applicable`, 전환 `주요 이벤트` |
| 메타 | `Reporting starts`, `Campaign name`, `Amount spent (KRW)`, `Results`, `Result type` | `Reporting starts` | `Amount spent (KRW)` | `Impressions`, `Link clicks` | `Results` | 결측 | VAT `unknown`, 전환은 `Result type` 값 |
| 네이버 검색광고 | `일별`, `총비용(VAT제외,원)`, `전환수`, `전환매출액(원)` | `일별` | `총비용(VAT제외,원)` | `노출수`, `클릭수` | `전환수` | `전환매출액(원)` | VAT `excluded`, 전환은 원본 정의 유지 |
| 네이버 GFA | `기간`, `광고비(VAT포함,원)`, `전환수(구매완료)` | `기간` | `광고비(VAT포함,원)` | `노출`, `클릭` | `전환수(구매완료)` | 결측 | VAT `included`, 전환 `구매완료` |
| 카카오 모먼트 | `일자`, `비용(원)`, `전환(구매)`, `전환값(원)` | `일자` | `비용(원)` | `노출수`, `클릭수` | `전환(구매)` | `전환값(원)` | VAT `unknown`, 전환 `구매` |

헤더 순서는 판별 조건에서 제외. 파일명은 오류 메시지와 추적에만 사용. 판별 점수가 동률이거나 등록되지 않은 헤더 조합이면 채널 추정 없이 파일 단위 실패.

GA4 첫 주석행은 `#` 접두사로 명시적 건너뛰기. 무제한 주석행 무시는 손상된 파일을 정상으로 오인할 위험이 있으므로 헤더 발견 전 허용 행 수에 상한 적용 권장.

## MVP 구현 범위

1. 단일 입력 폴더의 `.csv` 일괄 처리
2. 제공 5개 채널의 헤더 기반 자동 판별
3. UTF-8·UTF-8 BOM, 표준 CSV 인용부호, GA4 선행 주석행 지원
4. 네 종류 날짜 형식의 ISO 날짜 변환
5. 공통 8개 데이터 필드와 추적·의미 메타데이터 생성
6. 결측과 0의 구분, 정수형 지표 검증, 원본 행 연결
7. 채널별 정규화 CSV 5개 생성
8. 검증 성공 결과의 구글시트 탭별 일괄 업로드
9. 대상 탭 초기화 후 재작성 방식의 재실행 중복 방지
10. 업로드 후 전체 셀 범위 재조회 대조
11. 헤더, 필터, 고정 행, 열 너비, 숫자 형식, 탭 색상 반영
12. 선택적 `전주비교` CSV의 별도 탭 업로드

## 제외 범위

- 채널 로그인, 다운로드, 공식 API 연동 등 P1 자동화
- CPA·ROAS·전환율 등 P3 파생 지표 계산
- 전주 대비 비교와 주간 요약 생성
- 캠페인명 유사도 기반 통합과 접두사 자동 제거
- VAT 포함·제외 금액의 강제 환산
- GA4 주요 이벤트와 매체 구매 전환의 통합
- GA4 매출의 광고 매체별 기여 배분
- 입력에 없는 값의 추정·0 대체
- 알 수 없는 신규 헤더의 자동 추론
- MCP를 필수 실행환경으로 사용하는 배포 구조
- 임시 탭 교체와 원자적 최종 탭 전환
- `run_id`·입력 해시 기반 실행 멱등성 계약
- `import_runs`·`validation_issues` 운영 탭
- 독립된 읽기 전용 검증 CLI

## 실패 조건과 처리 수준

### 실행 중단 오류

- 파일 읽기 실패, 잘못된 CSV 인용, 지원하지 않는 문자 인코딩
- 헤더 미발견, 채널 미판별, 둘 이상 채널과 모호하게 일치
- 해당 채널의 필수 헤더 누락 또는 같은 의미 헤더의 중복
- 날짜·정수 필드 파싱 실패, 필수 식별자인 날짜·캠페인 결측
- 음수 비용·노출·클릭·전환·매출
- 클릭 수가 노출 수보다 큰 행
- 공통 키 중복이 발생하고 제거된 원본 차원 또는 의미 메타데이터가 서로 다른 경우
- 입력 행 수와 변환 성공·실패 행 수의 불일치
- 검증 완료 전 업로드 호출, 업로드 후 행 수·헤더 대조 실패

오류 발생 시 해당 실행 전체를 미반영 상태로 종료하는 방식 권장. 일부 파일만 시트에 반영하면 같은 실행의 데이터 완전성을 확인하기 어려움.

### 경고 후 진행 가능

- 원본에 없는 비용·노출·클릭·전환·매출의 결측
- VAT 기준 `unknown`
- 채널별 전환 정의 차이
- 날짜 범위 내 특정 일자 또는 채널 파일 누락
- 0 지표, 매우 큰 값, 전환이 클릭보다 큰 값 등 업무 규칙에 따라 가능성이 남은 이상치

경고는 데이터와 함께 기록하되 임의 보정 제외. 기간 완전성을 필수 조건으로 합의한 경우 특정 일자·채널 누락을 오류로 승격 가능한 설정 제공.

## 구글시트 출력 계약

실제 채널 탭은 `GA4`, `Meta`, `네이버 검색광고`, `네이버 GFA`, `카카오 모먼트`의 다섯 개. P4 산출물이 있으면 `전주비교` 탭 추가. 로컬 CSV는 공통 17개 영문 필드를 유지하되 시트의 모든 헤더는 한글 표시. 반복 정보인 채널 열과 기술 메타데이터 열은 값 보존 상태로 화면에서 숨김.

출력 계층에서 채널 코드 5종, 지표 코드 8종, 부가세 기준 4종, 비교 상태 2종을 한글 라벨로 변환. 캠페인명·원본 차원·파일명·해시·수치·결측은 원본 보존. 미등록 코드 발견 시 업로드 중단.

업로드 실행은 필요한 탭 생성, 대상 탭 범위 초기화, 전체 값 일괄 쓰기, 작성 범위 전체 재조회 대조, 탭별 서식 반영의 순서. 다른 탭은 변경 대상에서 제외. 헤더 굵기와 색상, 첫 행 고정, 기본 필터, 열 너비, 행 높이, 숫자 형식, 채널별 탭 색상 포함.

인증 정보는 `secret/` 아래 로컬 파일과 환경변수로만 전달하고 저장소에서 제외. 단순 확인은 쓰기 어댑터 실행 대신 읽기 전용 OAuth 범위를 사용. 세부 절차는 [P2 구글시트 API 사용 가이드](./P2_구글시트_API_사용가이드.md) 참조.

임시 탭 교체, `run_id` 기반 중복 판정, 실행·검증 전용 탭은 MVP 이후 운영 확장 범위.

## 검증 기준과 현재 상태

### 정규화 인수 기준

아래 항목은 정규화 전용 회귀 테스트가 아닌 구현·실데이터 인수 기준. 별도 테스트 모듈 추가 필요.

1. 헤더 순서를 바꾸어도 5개 채널 각각 정확히 판별
2. UTF-8 BOM, GA4 주석행, 쉼표가 포함된 인용 헤더의 정상 판독
3. `20260713`, `2026-07-13`, `07/13/2026`, `2026.07.13.`의 동일 ISO 날짜 변환
4. 각 원본 지표의 공통 필드 일대일 매핑과 결측 보존
5. 원본 파일별 행 수와 정규화 행 수 일치
6. 원본과 정규화 결과의 비용·노출·클릭·전환·매출 합계 일치. 결측 지표는 합계 비교 대상에서 제외
7. VAT와 전환 정의 메타데이터의 채널 규칙 일치
8. 미등록·모호·필수 헤더 누락·잘못된 숫자·중복 키 입력의 의도한 실패
9. 업로드 어댑터 미사용 상태에서도 로컬 정규화와 검증 완료
10. 동일 실행 재업로드 시 중복 행 미발생

### 출력 어댑터 자동화 시험

1. 대상 탭 생성·초기화·일괄 쓰기·전체 범위 재조회 대조
2. Google API의 행 끝 빈 셀 생략을 보정한 값 일치 판정
3. 채널 탭과 `전주비교` 탭의 서식 요청 생성 검증
4. 누락 채널 파일과 업로드 후 값 불일치의 실패 처리

`tests/integration/test_google_sheets_output.py`의 10개 테스트 통과. 한글 헤더와 코드 라벨 변환, 내부 스키마 불변, 미등록 코드 실패 처리 포함.

### 제공 데이터 인수 기준

- CSV 5개 모두 파일명이 아닌 헤더로 정확히 판별
- 입력의 모든 데이터 행에 `source_file`과 `source_row_number` 연결
- 날짜 범위 `2026-07-13`부터 `2026-07-26`까지 정상 변환
- GA4 비용·노출·클릭, 메타·GFA 매출의 결측 유지
- GFA 비용 `included`, 네이버 검색광고 비용 `excluded`, 메타·카카오 비용 `unknown` 유지
- GA4 주요 이벤트와 광고 채널 구매 계열 전환의 정의 분리
- 검증 오류 0건일 때만 업로드 가능 상태로 판정
- 업로드 완료 후 로컬 산출물과 시트의 행 수·헤더·표본 값 일치
- 채널별 탭 5개와 선택적 `전주비교` 탭의 전체 범위 일치
- 첫 행 고정, 기본 필터, 열 너비, 숨김 열, 탭 색상 반영

## 구현 순서 제안

1. 공통 스키마와 채널 레지스트리 확정
2. 제공 CSV 기반 골든 테스트 작성
3. 판독·판별·채널 어댑터 구현
4. 검증기와 로컬 산출물 구현
5. 실패 입력 시험과 재현성 확인
6. 구글시트 어댑터 구현
7. 탭별 서식과 선택적 전주 비교 출력 연결
8. 임시 탭 교체, 실행 기록, 읽기 전용 CLI의 운영 확장

현재 MVP 완료 기준은 동일 입력과 동일 규칙 버전으로 같은 채널별 정규화 CSV를 재생성하고 시트 전체 범위와 대조 가능한 상태. 별도 검증 보고서 재생성은 운영 확장 기준.
