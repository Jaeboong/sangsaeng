# 작업 진행 타임라인

## 기록 기준

- 대화 흐름을 기준으로 재구성한 상대 시간
- 정확한 타이머 계측이 아닌 작업 순서 확인용 구간
- 문제 담당 세션의 인수인계와 반환은 실제 시각 기준으로 별도 기록

## 진행 과정

| 구간 | 사용자 프롬프트 요약 | 사용자 결정과 결과 |
|---|---|---|
| 자동화 대상 결정 | 다운로드한 CSV를 구글시트로 옮기는 작업의 자동화 가능성 제시 | 사용자가 CSV의 구글시트 반영 자동화를 구현 대상으로 결정. P2의 목표로 반영 |
| 정규화 위치 결정 | MCP로 외부에서 처리하는 방식보다 프로그램 내부 정규화 방식 제안 | 사용자가 정규화를 로컬 프로그램 내부에서 처리한 뒤 구글시트에 올리는 구조로 결정 |
| 실행 흐름 결정 | CSV 다운로드 후 실행파일을 눌러 자동 정규화와 업로드를 진행하는 방식 제안 | 사용자가 `CSV 다운로드 → 실행파일 실행 → 자동 정규화 → 구글시트 업로드` 파이프라인으로 결정 |
| 문제별 분리 | 전체 업무를 P1~P5로 구분하고 P2를 별도 세션에 인수인계하도록 요청 | 사용자가 P1을 MVP 범위에서 제외하고 P2 방향을 `상생/019fc18e` 세션에 인수인계하도록 결정 |
| MVP 범위 확정 | 제한 시간 안에서 P4까지 설계·구현하고 P5는 사람의 영역으로 남기는 방향 제시 | 사용자가 객관적 계산과 반복 작업인 P2~P4까지 구현 범위로 결정. 주요 변화 선택과 성과 해석이 필요한 P5는 제외 |
| P4 출력 방식 결정 | 전주 대비 비교 결과를 별도 시트 탭에 정리하는 방식 제시 | 사용자가 P4 결과를 구글시트의 `전주비교` 탭에 업로드하는 방식으로 결정 |
| 통합 실행 방식 결정 | P2~P4 결과를 하나의 배치 실행 파일로 연결하고 경로·시트 설정을 환경 파일로 분리하도록 요청 | 사용자가 `.env` 기반 통합 실행과 지정 테스트 시트의 실제 업로드 검증을 결정. `원본 CSV → 정규화 → 파생 지표 → 전주 비교 → 검증 → 구글시트` 일괄 실행 결과 채택 |
| 시트 표시 언어 결정 | 영문 속성명과 코드값을 읽기 어렵다는 문제 제시 | 사용자가 구글시트 표시 계층의 한글화를 결정. 내부 CSV 스키마는 유지하고 6개 탭의 헤더·채널·지표·상태·부가세 코드만 한글 표시로 변환 |
| 최종 사용자 실행 방식 결정 | 비개발자가 터미널 명령을 실행하지 않는 단일 실행 파일 요구 | 사용자가 배치 파일이 아닌 Windows EXE를 최종 진입점으로 결정. Python 설치 없이 더블클릭 실행, 결과 대화상자, 동일 `.env`·입력·출력 구조로 연결 |

## 핵심 프롬프트 요약

### P2. 채널별 CSV 정규화와 구글시트 반영

- 담당 역할: 다운로드한 채널 CSV의 정규화와 구글시트 반영 구조 설계
- 사용자 결정: MCP나 구글시트 내부가 아닌 로컬 프로그램 내부에서 정규화한 뒤 구글시트에 업로드
- 핵심 흐름: `CSV 다운로드 → 실행 → 채널 자동 판별 → 정규화·검증 → 구글시트 업로드`
- 정규화 기준: 날짜·채널·캠페인·비용·노출·클릭·전환·매출의 공통 스키마
- 보존 기준: 원본에 없는 값은 결측으로 유지, VAT 기준과 전환 정의는 별도 정보로 보존, 의미가 다른 지표의 강제 합산 금지
- 구조 기준: 정규화 엔진과 구글시트 출력 어댑터 분리, MCP는 개발·검증 보조 수단으로 제한
- 반환 요청: 구현·제외 범위, 실패 조건, 검증 기준, 작업 시각, 생성·수정 파일, 검증 결과

### P3. 파생 지표 계산

- 담당 역할: P2 정규화 데이터를 이용한 CPA·ROAS·전환율 계산
- 계산 기준: `CPA = 비용 합계 ÷ 전환 합계`, `ROAS = 매출 합계 ÷ 비용 합계`, `전환율 = 전환 합계 ÷ 클릭 합계`
- 집계 기준: 행별 비율 평균 금지, 원천 지표를 먼저 합산한 뒤 비율 계산
- 제외 기준: 0 분모, 필수 값 결측, VAT 기준 혼합, 전환 정의 혼합 시 계산 제외와 사유 출력
- 채널 기준: GA4의 CPA·ROAS 제외, 메타·GFA의 ROAS 제외, 서로 다른 기준을 섞은 전체 채널 지표 제외
- 구조 기준: 그룹 기준을 입력받는 재사용 함수와 계산 불가 사유 필드, P4가 주차 기준으로 재사용할 수 있는 집계 인터페이스
- 경로 기준: `src/metrics/`, `tests/metrics/`, `docs/P3/`, `output/reports/`
- 반환 요청: 구현·제외 범위, 작업 시각, 생성·수정 파일, 테스트 명령과 결과

### P4. 전주 대비 비교

- 담당 역할: P3의 합계·파생 지표를 이용한 전주 대비 비교
- 입력 기준: `output/normalized/`의 채널별 정규화 CSV 5개와 P3 재사용 함수
- 기간 기준: 월요일~일요일 ISO 주간, 전주 `2026-07-13~07-19`, 금주 `2026-07-20~07-26`
- 비교 기준: 동일 채널·캠페인·지표의 전주 값과 금주 값
- 계산 기준: 증감과 증감률 계산, 전주 0·결측·기준 불일치 시 비교 제외 사유 출력
- 출력 기준: 구글시트의 별도 `전주비교` 탭에 업로드
- 제외 기준: 좋아짐·나빠짐 판단, 성과 맥락 해석, 요약 문장 작성
- 경로 기준: `src/comparison/`, `tests/comparison/`, `docs/P4/`, `output/reports/`
- 반환 요청: 작업 시각, 구현·제외 범위, 생성·수정 파일, 테스트 결과, 제공 데이터 결과 요약

### P5. 주간 요약 보고

사람의 판단이 필요한 영역으로 MVP에서 제외. 담당 세션 인수인계 없음.
