# 통합 파이프라인

## 목적

채널별 원본 CSV 투입 후 정규화, 파생 지표 계산, 전주 비교, 로컬 결과 저장, 구글시트 반영까지 한 번에 처리하는 사용자 실행 진입점.

## 실행 진입점

- 더블클릭 실행: `scripts/run_pipeline.bat`
- 터미널 실행: `scripts\run_pipeline.bat --no-pause`
- 통합 제어: `src/pipeline.py`
- 실행 설정: `.env`
- 제출용 설정 예시: `.env.example`

## 기본 처리 순서

```text
data/input의 원본 CSV
→ 5개 채널 판별과 공통 스키마 정규화
→ CPA·ROAS·전환율 계산
→ 전주 대비 증감 계산
→ 채널 탭 5개와 전주비교 탭 입력 검증
→ 로컬 CSV 교체
→ 구글시트 업로드와 재조회 검증
→ output/logs 실행 기록
```

## 기본 결과

| 구분 | 경로 또는 탭 |
|---|---|
| 채널별 정규화 CSV | `output/normalized/` |
| 파생 지표 CSV | `output/reports/derived_metrics.csv` |
| 전주 비교 CSV | `output/reports/weekly_comparison.csv` |
| 실행 로그 | `output/logs/` |
| 구글시트 채널 탭 | `GA4`, `Meta`, `네이버 검색광고`, `네이버 GFA`, `카카오 모먼트` |
| 구글시트 비교 탭 | `전주비교` |

## 중단 조건

- 입력 CSV 부재
- 지원 대상 5개 채널 중 하나 이상 누락
- 채널 판별 실패 또는 공통 키 중복
- 공통 스키마, 지표 계산, 주간 비교 결과 검증 실패
- 실제 업로드 설정에서 시트 ID 또는 서비스 계정 JSON 부재
- 구글시트 업로드 후 재조회 불일치

입력·계산·시트 입력 검증 통과 전 원격 쓰기 금지. `DRY_RUN=true` 또는 `--dry-run` 지정 시 로컬 결과 생성과 시트 입력 검증까지만 진행.

## 기간 선택

- 기본값: 입력 데이터에서 확인되는 최신 완전 주간
- 금주 시작일 고정: `.env`의 `CURRENT_WEEK_START=YYYY-MM-DD`
- 기준일 선택: `.env`의 `REFERENCE_DATE=YYYY-MM-DD`
- 두 설정의 동시 사용 금지

## 최초 준비

1. `.env.example`을 기준으로 `.env` 설정
2. `data/input/`에 채널별 CSV 배치
3. 서비스 계정 이메일에 대상 스프레드시트 편집 권한 부여
4. `google-api-python-client`, `google-auth` 설치
5. `scripts/run_pipeline.bat` 실행
